# Security Policy

## Reporting a vulnerability or exposed information

Do not post exploit details, secrets, or personal/student information in a public issue or pull request.

For a potential security issue affecting this repository or an example project, contact [info@iscexpo.edu.bd](mailto:info@iscexpo.edu.bd) privately. Include the affected path or project, a concise description, potential impact, and safe reproduction steps when appropriate. Do not attach real student records or credentials.

If a credential has been exposed, revoke or rotate it promptly. When reporting it, identify the location of the exposure but do not send the credential itself. If personal information is exposed, share only enough detail privately to locate it and do not copy or redistribute it.

Maintainers should acknowledge the report, limit access to its details, investigate, and coordinate remediation privately. Response times may vary while maintainer capacity is confirmed. Please allow a reasonable opportunity to investigate before public disclosure.

## Safe learning environments

Examples should avoid real credentials, production data, destructive defaults, and unnecessary external services. Read commands before running them and use a disposable environment for unfamiliar operations.
